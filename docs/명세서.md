# 문서 규칙 점검기 — 구현 명세서

## 1. 개요

- 서비스: 문서 작성 규칙 자동 점검 웹 프로토타입
- 해결 문제: 문서 검토 시간이 형식 지적에 소모되어 내용 검토 부족
- 사용자: 작성자(개발자), 검토자(PL·QA)
- 핵심 흐름: 문서 입력 → 규칙 점검 → 위반 목록·수정안 확인 → 수정 → 검토 요청 → 승인 → 문서목록 등록
- 근거 자료: 3차 과제 「AI 활용 서비스 기획안」

## 2. 확정 사항

| 항목 | 결정 | 이유 |
|---|---|---|
| 입력 방식 | 본문 붙여넣기 + 파일명 입력. docx 업로드 미구현 | 브라우저 docx 해석 불안정 → 시연 실패 위험 |
| 로그인 | 미구현. 상단 역할 전환(작성자 / 검토자) | 평가자가 계정 없이 두 역할 화면 확인 필요 |
| 코드 규칙 | 실제 판정 (정규식·구조 검사) | 입력 변경 시 결과 변화 → 실제 서비스 체감 |
| AI 규칙 | 패턴 기반 모의 판정. 화면에 "AI 판정 (시연용)" 표기 | 실제 LLM 미연동. 평가자 오해 방지 |
| 백엔드 | 없음. 상태는 localStorage | 정적 사이트 → GitHub Pages 배포 |
| 스택 | Vite + React + TypeScript + Tailwind CSS | 다중 화면 컴포넌트 구성, Pages 배포 용이 |
| 배포 | GitHub Actions → GitHub Pages | 공개 URL 제출 요건 |
| 데이터 | 가상 데이터만 | 공개 저장소·공개 URL |

## 3. 화면

### 3.1 공통

- 상단 바: 서비스명 "문서 규칙 점검기", 메뉴(점검 / 검토함 / 문서목록 / 규칙집), 역할 전환 토글
- 한국어 UI, 업무용 톤 (진남색 계열 강조색)
- 데스크톱 우선, 모바일 폭에서 깨짐 없음
- 첫 진입 화면: 점검 입력. 상단에 서비스 한 줄 소개 + "샘플로 바로 체험" 안내

### 3.2 점검 입력 (작성자)

- 문서 종류 선택: 시험결과보고서 / 회의록 / 절차서
- 파일명 입력
- 본문 입력 (textarea, 절 구조 안내 placeholder)
- 샘플 불러오기 버튼 3개 (5절 샘플) — 클릭 시 종류·파일명·본문 자동 입력
- "점검하기" 버튼 → 결과 화면

### 3.3 점검 결과 (작성자)

- 판정 상태 배지: "보완 필요"(빨강) / "검토 요청 가능"(초록)
- 필수·권고 건수 요약
- 위반 목록 표
	- 열: 위치(절·행), 규칙 ID, 위반 내용, 수정안, 심각도, 판정 주체(코드 / AI 시연), 조치
	- 조치: 권고 → 수락·거부 버튼. 필수 → 본문 직접 수정 안내 또는 자동 수정 가능 항목은 "적용" 버튼
- 원문 패널: 위반 줄 강조 표시, 목록 행 클릭 시 해당 줄로 이동
- 근거 조항 패널: 선택 위반의 규칙 원문
- "본문 수정 후 재점검" — 본문 편집 가능, 재점검 시 결과 갱신
- "수정본 미리보기" → 3.4
- "검토 요청" 버튼: 필수 0건일 때만 활성. 비활성 시 사유 툴팁

### 3.4 수정본 미리보기

- 수락·적용 항목 반영 본문
- 변경 줄 전후 비교 (삭제 취소선 / 추가 강조)
- 텍스트 파일 다운로드
- "수정본으로 재점검" 버튼

### 3.5 검토 요청

- 검토자 선택 (가상: 검토자A, 검토자B)
- 요청 메모 입력
- 요청 시 상태 "검토 대기", 알림 토스트 ("검토자A에게 검토 요청 알림 발송 (시연)")

### 3.6 검토함 (검토자)

- 검토 대기 목록: 파일명, 문서 종류, 요청자, 요청 시각, 권고 잔여 건수
- 상세: 본문, 점검 결과 요약(작성자 거부 권고 항목 포함)
- 승인 / 반려(사유 필수)
- 승인 → 문서목록 자동 등록. 반려 → 작성자 화면에 반려 사유 표시

### 3.7 문서목록

- 승인 문서 목록: 문서명, 종류, 승인자, 승인 시각
- 초기 데이터: 가상 등록 문서 2~3건

### 3.8 규칙집 + 규칙 질의

- 규칙 9개 목록, 문서 종류 필터 (공통 / 회의록 / 절차서)
- 각 규칙: ID, 규칙, 판정 주체, 심각도, 규칙 존재 이유
- 질의 입력창 ("이 규칙 왜 있어?")
	- 키워드 매칭 → 관련 규칙 + 근거 답변 표시
	- "AI 답변 (시연용)" 표기
	- 예시 질문 칩 3개: "파일명 날짜는 언제 기준이야?", "결정 이유는 어느 정도로 써야 해?", "주의사항에 뭘 넣어야 해?"

## 4. 규칙 및 판정 로직

### 4.1 입력 구조 전제

- 첫 줄 부근 `작성일: YYYY-MM-DD`
- 절 제목: `숫자. 제목` (예: `1. 시험 결과`)
- 절 내용: 제목 다음 줄부터 다음 절 제목 전까지

### 4.2 규칙

| ID | 대상 | 규칙 | 판정 | 심각도 |
|---|---|---|---|---|
| C-01 | 공통 | 파일명 `[프로젝트]_[문서명]_[yyyyMMdd].확장자` | 코드 | 필수 |
| C-02 | 공통 | 파일명 날짜 = 본문 작성일 | 코드 | 필수 |
| C-03 | 공통 | 설명부 개조식 (명사형 종결) | AI 시연 | 권고 |
| C-04 | 공통 | 한 문장 한 내용 | AI 시연 | 권고 |
| C-05 | 공통 | 마지막 절 "문서 이력" | 코드 | 필수 |
| C-06 | 공통 | 결정 사항에 이유 기재 | 코드 / AI 시연 | 필수 / 권고 |
| M-01 | 회의록 | Action Item 담당·기한 기재 | 코드 / AI 시연 | 필수 / 권고 |
| P-01 | 절차서 | 수행 단계 번호 부여 | 코드 | 필수 |
| P-02 | 절차서 | 주의사항은 사고 유발 사항만 | AI 시연 | 권고 |

### 4.3 판정 방법

- C-01: `^[^_]+_[^_]+_\d{8}\.(docx|md|txt)$` 불일치 → 위반
	- 수정안: 파일명 내 날짜를 작성일 기준 `yyyyMMdd`로 치환한 이름
	- 자동 적용 가능
- C-02: 파일명 날짜(`yyyyMMdd`, `yyyy.MM.dd`, `yyyy-MM-dd` 모두 추출) ≠ 작성일 → 위반. 작성일 없음 → 위반
- C-03: 줄 끝이 `습니다|하였다|했다|한다|된다|바랍니다|입니다` (마침표 허용) → 위반
	- 수정안: 샘플 문장은 사전 정의 문장. 그 외 "명사형 종결로 수정 (예: ~발생, ~수행, ~확인)"
- C-04: 줄에 `하였고|했고|되었고|이며|하며` 포함 → 위반
	- 수정안: 연결어미 기준 두 항목 분리 제시
- C-05: 마지막 절 제목 ≠ "문서 이력" → 위반
	- 수정안: 문서 이력 절 템플릿 추가. 자동 적용 가능
- C-06: "결정 사항" 절 각 줄
	- `이유:` 없음 또는 빈 값 → 필수
	- 이유가 `협의 결과|논의 결과|회의 결과|검토 결과` 또는 6자 미만 → 권고
	- 수정안: "결정을 뒤집으려는 사람을 막는 근거 기재 필요" + 작성자 입력 요청. AI 이유 생성 금지
- M-01: 회의록 "Action Item" 절 각 줄
	- `담당:` 또는 `기한:` 없음·빈 값 → 필수
	- 기한이 `YYYY-MM-DD` 아님 → 권고
	- 수정안: "구체 날짜 기재 (예: 2026-10-13)"
- P-01: 절차서 "수행 절차" 절 각 줄이 `^\d+[).]` 아님 → 필수
	- 수정안: 앞뒤 단계 번호 기준 번호 부여. 자동 적용 가능
- P-02: 절차서 "주의사항" 절 각 줄에 `손상|오동작|유실|금지|화재|감전|파손|오결선|사고|위험` 없음 → 권고
	- 수정안: "사고 무관 항목 삭제 검토"

### 4.4 판정 상태

- 필수 1건 이상 → 보완 필요, 검토 요청 불가
- 필수 0건 → 검토 요청 가능 (권고 잔여 허용)

## 5. 샘플 문서

### 5.1 시험결과보고서 — 기대: 보완 필요 (필수 3 / 권고 3)

파일명: `가상레이더_시험결과보고서_2026.10.05.docx`

```
작성일: 2026-10-06

1. 시험 개요
시험 대상: 가상레이더 통신 모듈
시험 일자: 2026-10-05
2. 시험 결과
시험 중 통신이 끊기는 현상이 발생하여 원인을 분석하였습니다.
SBC 재부팅 후 정상 동작을 확인하였고 로그는 서버에 업로드함
3. 결정 사항
기존 메시지 형식 현행 유지 / 이유: 협의 결과
```

- 필수: C-01(날짜 형식), C-02(10-05 ≠ 10-06), C-05(문서 이력 없음)
- 권고: C-03(분석하였습니다), C-04(확인하였고), C-06(협의 결과)
- C-03 수정안: "시험 중 통신 두절 현상 발생, 원인 분석 수행"
- C-04 수정안: "SBC 재부팅 후 정상 동작 확인" / "로그 서버 업로드 완료"

### 5.2 회의록 — 기대: 검토 요청 가능 (필수 0 / 권고 1)

파일명: `가상레이더_주간회의록_20261006.md`

```
작성일: 2026-10-06

1. 회의 개요
일시: 2026-10-06 10:00
참석: 작성자A, 작성자B
2. 결정 사항
통신 타임아웃 500ms 유지 / 이유: 타 장비 응답 지연 최대 420ms
3. Action Item
인터페이스 시험 결과 공유 / 담당: 작성자A / 기한: 다음 주쯤
타임아웃 설정값 문서 반영 / 담당: 작성자B / 기한: 2026-10-10
4. 문서 이력
v1.0 / 2026-10-06 / 최초 작성
```

- 권고: M-01(기한 "다음 주쯤")

### 5.3 절차서 — 기대: 보완 필요 (필수 1 / 권고 1)

파일명: `가상레이더_통신시험절차서_20261006.md`

```
작성일: 2026-10-06

1. 목적
가상레이더 통신 모듈 기능 시험 절차 정의
2. 수행 절차
1) 시험 장비 전원 인가
시험 프로그램 실행
3) 송수신 로그 저장
3. 주의사항
전원 인가 전 케이블 연결 확인 — 오결선 시 장비 손상
시험 프로그램 실행 속도 느림, 참고
4. 문서 이력
v1.0 / 2026-10-06 / 최초 작성
```

- 필수: P-01(2단계 번호 없음)
- 권고: P-02(실행 속도 느림)

## 6. 검증 기준

- 샘플 3종 점검 결과가 5절 기대 건수와 일치
- 보고서: 자동 적용(C-01, C-05) + 본문 수정 후 재점검 → 필수 0건 → 검토 요청 → 검토자 승인 → 문서목록 등록까지 끊김 없이 진행
- 파일명만 고쳐도 C-01·C-02 즉시 해소
- 새로고침 후에도 검토 요청·승인 상태 유지 (localStorage)
- 배포 URL을 시크릿 창에서 열어 동작 확인
