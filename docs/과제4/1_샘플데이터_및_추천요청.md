# 과제 4 — 1단계: 샘플 데이터 및 모델 추천 요청

> 중간평가 「문서 규칙 점검기」의 입력·출력 정의를 바탕으로 준비한 샘플. 모든 데이터는 가상 데이터.

## 1. 입력·출력 정의

### 입력 (Input)

| 항목 | 내용 |
|---|---|
| 문서 종류 | 시험결과보고서 / 회의록 / 절차서 |
| 파일명 | 예: `가상레이더_시험결과보고서_20261006.docx` |
| 본문 | 첫 줄 `작성일: YYYY-MM-DD`, 절 제목 `숫자. 제목`, 절 내용은 다음 절 제목 전까지 |

### 출력 (Output)

위반 목록 + 판정 상태 (JSON)

```json
{
  "status": "보완 필요 | 검토 요청 가능",
  "violations": [
    {
      "ruleId": "C-03",
      "location": "2. 시험 결과 · 7행",
      "severity": "필수 | 권고",
      "judge": "code | ai",
      "message": "위반 내용",
      "suggestion": "수정안"
    }
  ]
}
```

## 2. 규칙과 AI 적용 범위

| ID | 규칙 | 판정 | AI 필요 |
|---|---|---|:---:|
| C-01 | 파일명 `[프로젝트]_[문서명]_[yyyyMMdd].확장자` | 코드 | |
| C-02 | 파일명 날짜 = 본문 작성일 | 코드 | |
| C-03 | 설명부 개조식 (명사형 종결) | AI | ✅ |
| C-04 | 한 문장 한 내용 | AI | ✅ |
| C-05 | 마지막 절 "문서 이력" | 코드 | |
| C-06 | 결정 사항에 이유 기재 (누락=코드 필수 / 불충분=AI 권고) | 코드+AI | ✅ |
| M-01 | Action Item 담당·기한 (누락=코드 필수 / 모호=AI 권고) | 코드+AI | ✅ |
| P-01 | 수행 단계 번호 부여 | 코드 | |
| P-02 | 주의사항은 사고 유발 사항만 | AI | ✅ |

- 형식 규칙은 정규식으로 확정 판정 가능 → AI 불필요
- **AI가 필요한 것은 문맥 판단 5개 규칙 + 규칙 질의 답변**

## 3. 샘플 데이터

### 샘플 1 — 시험결과보고서 (기대: 보완 필요, 필수 3 / 권고 3)

파일명: `가상레이더_시험결과보고서_2026.10.05.docx`

```
작성일: 2026-10-06

1. 시험 개요
시험 대상: 가상레이더 통신 모듈
시험 일자: 2026-10-05
2. 시험 결과
시험 중 통신이 끊기는 현상이 발생하여 원인을 분석하였습니다.
SBC 재부팅 후 정상 동작을 확인하였고 로그는 서버에 업로드함
3. 결정 사항
기존 메시지 형식 현행 유지 / 이유: 협의 결과
```

기대 출력:

```json
{
  "status": "보완 필요",
  "violations": [
    { "ruleId": "C-01", "location": "파일명", "severity": "필수", "judge": "code",
      "message": "파일명 형식 불일치 (날짜 구분자)", "suggestion": "가상레이더_시험결과보고서_20261006.docx" },
    { "ruleId": "C-02", "location": "파일명", "severity": "필수", "judge": "code",
      "message": "파일명 날짜 2026.10.05 ≠ 작성일 2026-10-06", "suggestion": "가상레이더_시험결과보고서_20261006.docx" },
    { "ruleId": "C-03", "location": "2. 시험 결과 · 7행", "severity": "권고", "judge": "ai",
      "message": "서술형 종결 — 개조식 아님", "suggestion": "시험 중 통신 두절 현상 발생, 원인 분석 수행" },
    { "ruleId": "C-04", "location": "2. 시험 결과 · 8행", "severity": "권고", "judge": "ai",
      "message": "\"하였고\"로 두 내용 연결", "suggestion": "SBC 재부팅 후 정상 동작 확인 / 로그 서버 업로드 완료" },
    { "ruleId": "C-06", "location": "3. 결정 사항 · 10행", "severity": "권고", "judge": "ai",
      "message": "이유 \"협의 결과\" — 근거 불충분", "suggestion": "수치·제약·대안 비교 등 근거 기재 (작성자 직접 입력)" },
    { "ruleId": "C-05", "location": "문서 끝", "severity": "필수", "judge": "code",
      "message": "마지막 절이 \"문서 이력\" 아님", "suggestion": "4. 문서 이력 / v1.0 / 2026-10-06 / 최초 작성" }
  ]
}
```

### 샘플 2 — 주간회의록 (기대: 검토 요청 가능, 필수 0 / 권고 1)

파일명: `가상레이더_주간회의록_20261006.md`

```
작성일: 2026-10-06

1. 회의 개요
일시: 2026-10-06 10:00
참석: 작성자A, 작성자B
2. 결정 사항
통신 타임아웃 500ms 유지 / 이유: 타 장비 응답 지연 최대 420ms
3. Action Item
인터페이스 시험 결과 공유 / 담당: 작성자A / 기한: 다음 주쯤
타임아웃 설정값 문서 반영 / 담당: 작성자B / 기한: 2026-10-10
4. 문서 이력
v1.0 / 2026-10-06 / 최초 작성
```

기대 출력: `M-01` (9행) 권고 — 기한 "다음 주쯤" 구체 날짜 아님 → "구체 날짜 기재 (예: 2026-10-13)"

### 샘플 3 — 통신시험 절차서 (기대: 보완 필요, 필수 1 / 권고 1)

파일명: `가상레이더_통신시험절차서_20261006.md`

```
작성일: 2026-10-06

1. 목적
가상레이더 통신 모듈 기능 시험 절차 정의
2. 수행 절차
1) 시험 장비 전원 인가
시험 프로그램 실행
3) 송수신 로그 저장
3. 주의사항
전원 인가 전 케이블 연결 확인 — 오결선 시 장비 손상
시험 프로그램 실행 속도 느림, 참고
4. 문서 이력
v1.0 / 2026-10-06 / 최초 작성
```

기대 출력: `P-01` (7행) 필수 — 단계 번호 없음 → "2) 시험 프로그램 실행" / `P-02` (11행) 권고 — 사고 유발 사항 아님 → "삭제 검토"

### 샘플 4 — 패턴 판정의 한계 사례 (AI 필요성 확인용)

파일명: `가상레이더_시험결과보고서_20261020.docx`

```
작성일: 2026-10-20

1. 시험 결과
수신 지연 현상은 버퍼 크기 부족이 원인으로 판단되어 설정값을 늘린 뒤 재시험을 진행했으며 결과는 정상임
송신 모듈 점검 완료, 이상 없음
원인 상세 분석은 다음 시험에서 진행할 예정입니다.
2. 결정 사항
버퍼 크기 4KB → 8KB 변경 / 이유: 최대 수신 패킷 6.2KB 대비 여유 확보
재시험 일정 1주 연기 / 이유: 장비 사정
타임아웃 500ms 유지 / 이유: 검토 결과 실측 최대 지연 420ms로 기준 이내
3. 문서 이력
v1.0 / 2026-10-20 / 최초 작성
```

| 행 | 사람의 판단 (기대 출력) | 현재 패턴 판정 | 결과 |
|---|---|---|---|
| 4 | C-04 권고 — 원인 판단·조치·결과 3개 내용 연결 | 판정 없음 ("~했으며" 미등록) | ❌ 놓침 |
| 5 | 위반 없음 | 위반 없음 | ✅ |
| 6 | C-03 권고 — 서술형 종결 | C-03 권고 | ✅ |
| 9 | C-06 권고 — "장비 사정" 근거 불충분 | C-06 권고 | ✅ |
| 10 | 위반 없음 — 수치 근거 충분 | C-06 권고 ("검토 결과" 문구 포함) | ❌ 오탐 |

→ 패턴은 **표현이 조금만 달라도 놓치고(4행), 단어만 보고 오탐(10행)**. 문맥을 이해하는 모델이 필요한 이유.

## 4. 모델 추천 요청 프롬프트

LLM에 위 샘플과 함께 아래 질문을 제공.

```
사내 문서 작성 규칙을 자동 점검하는 서비스를 만들고 있어.
형식 규칙(파일명, 날짜, 절 구조)은 정규식으로 판정하고,
문맥 규칙 5개(C-03 개조식, C-04 한 문장 한 내용, C-06 결정 이유 충분성,
M-01 기한 구체성, P-02 주의사항 적합성)는 AI로 판정하려고 해.

위 샘플 입력과 기대 출력을 보고, 문맥 규칙 판정에 적합한
AI 모델 또는 알고리즘을 3가지 내외로 추천해줘.

조건:
- 한국어 업무 문서
- 출력은 위 JSON 형식 (위치, 규칙 ID, 위반 내용, 수정안)
- 규칙 원문을 근거로 판정해야 함
- 사내 문서라 보안도 고려해야 함
- 샘플 4처럼 표현이 달라도 잡고, 단어만 보고 오탐하지 않아야 함

각 추천마다 작동 원리, 장단점, 추천 이유를 알려줘.
```
